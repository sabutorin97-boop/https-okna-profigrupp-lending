# Бот для Авито — сводка перед началом работы

Документ для нового диалога: здесь всё, что уже выяснено и решено, чтобы
не начинать с нуля. Написан 21 августа 2026 года.

## Что нужно сделать

Бот отвечает на сообщения в чатах объявлений Авито и доводит обращение
до заявки на замер. Владелец выбрал два дела из четырёх предложенных:

1. **Отвечать на сообщения** — клиент пишет в объявление, бот отвечает сразу,
   не давая обращению остыть, пока менеджер занят.
2. **Собирать контакты и вести к замеру** — бот задаёт короткие вопросы
   и передаёт готовую заявку менеджеру.

Что делать **не** нужно: управлять объявлениями (публикация, поднятие,
статистика). Это отдельная задача, сейчас она не ставится.

**Размещение:** тот же сервер Timeweb, где живёт сайт. Отдельный сервер
не заводим.

## Главное препятствие

**Доступ к API Авито зависит от тарифа кабинета.** По официальной документации:

| Вертикаль | При каком тарифе доступен API |
|---|---|
| Товары, Работа | только «Максимальный» |
| Услуги | «Расширенный» и «Максимальный» |

У владельца есть кабинет Авито Про, но **ключей нет и тариф не проверен**.
Это первое, что нужно выяснить: без нужной подписки ключи не выдадут,
и обойти это кодом невозможно.

Где брать ключи: кабинет продавца → **Настройки → Авито API → зарегистрировать
новое приложение**. На выходе `client_id` и `client_secret`.

## Что выяснено про API

Проверено по официальной спецификации OpenAPI (238 путей), а не по памяти.
Спецификация лежит в открытом репозитории
[MissiaL/avito-api](https://github.com/MissiaL/avito-api),
файл `references/avito-api-openapi.json` — при необходимости скачивается
через `raw.githubusercontent.com`, этот адрес из рабочей среды доступен.

Сам сайт `developers.avito.ru` из среды разработки **закрыт** сетевой
политикой — проверить что-либо на нём не получится.

### Адрес и авторизация

Базовый адрес: `https://api.avito.ru`

Токен: `POST /token`, тело `application/x-www-form-urlencoded`,
способ `client_credentials`. В ответе `access_token`, `expires_in`
(время жизни в секундах) и `token_type`. Токен нужно кэшировать
и обновлять по истечении, а не запрашивать на каждое сообщение.

Права (scope), которые понадобятся:

- `messenger:read` — чтение сообщений и работа с подписками на уведомления;
- `messenger:write` — отправка сообщений.

Токен передаётся заголовком `Authorization: Bearer ТОКЕН`.

### Нужные методы

| Метод | Путь | Зачем |
|---|---|---|
| POST | `/messenger/v3/webhook` | включить уведомления о новых сообщениях |
| POST | `/messenger/v1/subscriptions` | посмотреть, какие подписки уже есть |
| POST | `/messenger/v1/webhook/unsubscribe` | отключить уведомления |
| POST | `/messenger/v1/accounts/{user_id}/chats/{chat_id}/messages` | ответить в чат |
| GET | `/messenger/v2/accounts/{user_id}/chats` | список чатов |
| GET | `/messenger/v3/accounts/{user_id}/chats/{chat_id}/messages/` | история переписки |
| POST | `/messenger/v1/accounts/{user_id}/chats/{chat_id}/read` | пометить прочитанным |
| GET | `/core/v1/accounts/self` | узнать свой `user_id` |

### Подписка на уведомления

```json
{
  "url": "https://окна-курган-профигруп.рф/avito/webhook.php",
  "secret": "сгенерированный ключ"
}
```

Оба поля обязательны. Подлинность приходящего уведомления проверяется
по заголовку `x-avito-messenger-signature`.

### Что приходит при новом сообщении

Схема `WebhookMessage`:

| Поле | Что означает |
|---|---|
| `id` | идентификатор сообщения |
| `chat_id` | чат, куда писать ответ |
| `author_id` | кто написал — по нему отсекаем собственные сообщения |
| `chat_type` | `u2i` — чат по объявлению, `u2u` — по профилю, `a2u` — от Авито |
| `item_id` | номер объявления, только для `u2i` |
| `content` | содержимое сообщения |
| `created` | время в виде unix-timestamp |
| `published_at` | время в формате RFC3339, UTC |

### Ответ в чат

```json
{
  "type": "text",
  "message": { "text": "Здравствуйте! Подскажу по остеклению." }
}
```

**Ограничение: 1000 знаков на сообщение.** Длинные ответы придётся делить
или сокращать.

## Как предлагается устроить бота

Тот же подход, что и на сайте: PHP без сборки, никаких зависимостей,
файлы заливаются на сервер как есть.

```
avito/
  webhook.php   приём уведомлений от Авито: проверка подписи, запуск диалога
  api.php       работа с API: токен с кэшем, отправка сообщений, подписка
  dialog.php    логика разговора — чистые функции, их легко проверить
  setup.php     помощник настройки: ключи, подписка на уведомления, проверка
  state/        состояние диалогов, по файлу на чат (вне папки сайта)
```

### Принципы, которые стоит соблюсти

- **Отвечать Авито сразу.** Вебхук должен вернуть `200` быстро, иначе
  Авито сочтёт доставку неудачной и будет повторять.
- **Не разговаривать с собой.** Если `author_id` совпадает с нашим
  `user_id` — это наше же сообщение, бот обязан промолчать. Иначе
  зацикливание.
- **Замолкать, когда пришёл менеджер.** Как только в чат написал человек
  из компании, бот перестаёт вести диалог по этому чату.
- **Коротко.** В переписке шесть вопросов, как в квизе на сайте,
  раздражают. Два-три, не больше.
- **Стоп-слово.** Клиент должен иметь возможность попросить живого
  человека и сразу его получить.
- **Согласие на обработку данных.** Бот спрашивает телефон, значит
  в сообщении должна быть ссылка на политику: `/privacy.html`.

### Куда попадёт заявка

Ничего нового изобретать не нужно — всё уже работает. В корне проекта
лежит `delivery.php`: журнал на диске, письмо, сообщение в MAX.
Бот вызывает `deliver_lead()` с меткой **«Авито»**, и заявка приходит
туда же, куда заявки с сайта, только с другой пометкой.

Модуль уже вынесен из `send.php` специально ради этого — 21 августа,
коммит «Доставка заявок вынесена в общий модуль delivery.php».

## Открытые вопросы

1. **Тариф кабинета Авито** — главный. Без него всё остальное не имеет смысла.
2. **Правила площадки.** Разрешены ли автоответы и запрос телефона в чате —
   проверить не удалось, `avito.ru` из рабочей среды закрыт. Стоит сверить
   с правилами, чтобы не поймать ограничение аккаунта.
3. **Где хранить код.** Сейчас предполагается папка `avito/` в репозитории
   сайта: сервер тот же, выкладка уже настроена, `delivery.php` рядом.
   Если владелец захочет отдельный репозиторий — переезд несложный.
4. **Тексты бота.** Что именно он пишет клиенту, нужно согласовать с владельцем:
   это лицо компании, а не техническая деталь.

## Что уже готово в проекте

Всё перечисленное работает и проверено на живом сервере:

- сайт с квизом на `окна-курган-профигруп.рф`;
- приём заявок: журнал на сервере, письмо на `potolok-45@yandex.ru`,
  сообщение в MAX — три чата, метка «Квиз форма»;
- `delivery.php` — общий модуль доставки, готов принять второй источник;
- `setup-config.php` — помощник настройки, задаёт вопросы и пишет `config.php`
  сам; у него есть режим проверки `--check`;
- автоматическая выкладка: коммит в `main` → сайт обновился за минуту.

### Грабли, на которые уже наступили

Пригодится: те же ловушки ждут и бота.

- На сервере не было `php-curl` и `php-mbstring` — без них падали и отправка
  в MAX, и приём заявок. Оба добавлены в `deploy/setup-server.sh`.
- `config.php`, созданный от `root`, был недоступен сайту (`www-data`).
  Теперь помощник сам отдаёт файл нужной группе и проверяет читаемость.
- Консоль Timeweb при вставке из буфера добавляет метки `[200~` и `[201~`
  прямо внутрь значения. Токен выглядит целым, а сервер отвечает
  «Invalid access_token». Помощник эти метки срезает.
- Сервер живёт по UTC — время в заявке нужно переводить в курганское,
  иначе менеджер видит время на пять часов раньше.

## С чего начать в новом диалоге

1. Спросить владельца про тариф кабинета Авито и ключи.
2. Пока ключей нет — писать `api.php` и `dialog.php`: логика разговора
   проверяется без всякого Авито, обычными тестами.
3. Согласовать тексты бота.
4. Когда появятся ключи — настроить подписку на уведомления и проверить
   на живом чате.
